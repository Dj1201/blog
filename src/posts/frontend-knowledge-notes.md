前端不只是把页面“画出来”，它更像是在浏览器里组织一套可交互、可维护、可持续迭代的体验。下面这份笔记把常见知识点串成一条主线，方便复习，也方便在做项目时快速对照。

## 1. HTML：先把内容结构搭好

HTML 负责描述内容的语义。写页面时不要只想着样式，先想清楚这块内容是什么。

- 标题用 `h1` 到 `h6` 表示层级，不要为了字号随意跳级。
- 导航用 `nav`，主要内容用 `main`，独立文章用 `article`，辅助信息用 `aside`。
- 表单控件要配合 `label`，这样对可访问性和点击体验都更友好。
- 图片要写有意义的 `alt`，装饰图可以留空 `alt=""`。

好的 HTML 会让页面更容易被搜索引擎、屏幕阅读器和后续维护者理解。

## 2. CSS：布局先于装饰

CSS 的核心不是“调颜色”，而是稳定地控制布局、层级和响应式表现。

常用布局可以这样选：

- 一维排列用 Flexbox，例如按钮组、导航栏、卡片内的横向信息。
- 二维布局用 Grid，例如文章列表、仪表盘、图片墙。
- 页面宽度用 `max-width` 和 `margin: auto` 控制，不要让正文在大屏上铺得过长。
- 响应式优先考虑内容如何重排，再补媒体查询。

一个常见的基础容器写法：

```css
.container {
  width: min(100% - 32px, 960px);
  margin-inline: auto;
}
```

这段代码可以让内容在手机端保留左右留白，在桌面端限制最大阅读宽度。

## 3. JavaScript：关注状态和事件

JavaScript 负责处理交互逻辑。写 JS 时可以多问三个问题：

- 当前页面有哪些状态？
- 用户的哪个动作会改变状态？
- 状态变化后，界面需要更新什么？

例如搜索框的逻辑可以拆成：输入关键词、保存关键词、根据关键词过滤列表、渲染结果。拆清楚之后，代码通常会更好维护。

```js
const keyword = input.value.trim().toLowerCase();

const result = posts.filter((post) => {
  return post.title.toLowerCase().includes(keyword);
});
```

复杂交互里，尽量避免让多个地方同时修改同一个状态。状态入口越少，问题越容易定位。

## 4. 浏览器渲染：页面为什么会变慢

浏览器大致会经历这些步骤：

1. 解析 HTML，生成 DOM。
2. 解析 CSS，生成 CSSOM。
3. 合并 DOM 和 CSSOM，生成渲染树。
4. 计算布局，也就是每个元素的位置和尺寸。
5. 绘制像素并合成到屏幕。

如果频繁读取和修改布局信息，就可能触发额外的布局计算。例如在循环里反复读取 `offsetHeight` 后又修改样式，就容易造成性能浪费。

更稳妥的做法是批量读取、批量修改：

```js
const height = panel.offsetHeight;

requestAnimationFrame(() => {
  panel.style.transform = `translateY(${height}px)`;
});
```

动画优先使用 `transform` 和 `opacity`，通常比直接修改 `top`、`left`、`width` 更平滑。

## 5. 性能优化：先做最有收益的事

前端性能优化不必一开始就追求复杂方案。很多时候，先做好这些就已经很有效：

- 图片按需压缩，优先使用合适尺寸，不上传超大原图。
- 首屏不需要的代码延迟加载。
- 列表渲染时给稳定的 `key`，避免不必要的重建。
- 避免一次性渲染过多 DOM，长列表可以考虑分页或虚拟列表。
- 请求结果可以缓存，重复数据不要反复请求。
- 打包前检查依赖体积，避免为了一个小功能引入过大的库。

判断性能问题时，先用浏览器 DevTools 看数据，再决定怎么改。凭感觉优化很容易把时间花在收益很小的地方。

## 6. 工程化：让项目长期可维护

一个前端项目变复杂后，真正影响效率的往往是工程习惯。

- 目录结构要清晰：页面、组件、工具函数、样式各放各的位置。
- 组件只做一件主要事情， props 和事件命名要直接。
- 公共逻辑提取成函数或 composable，但不要过早抽象。
- 提交前跑一遍构建，至少保证主流程不会坏。
- 写 README 或注释时，记录“为什么这样做”，不要只重复代码表面含义。

## 小结

学习前端可以按照这条路线推进：先理解 HTML 语义，再掌握 CSS 布局，然后用 JavaScript 管理状态和交互，最后补上浏览器渲染、性能优化和工程化思维。

真正的提升通常来自不断做项目、遇到问题、复盘问题。每一次把一个页面做得更清晰、更快、更稳定，都是前端能力的一小步升级。
