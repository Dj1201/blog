前端问题看起来很散：有时候是样式不生效，有时候是接口请求失败，有时候是本地能跑、线上白屏。真正高效的排查方式不是盲改，而是先确认问题发生在哪一层。

## 1. 页面样式没有生效

先按这个顺序查：

- CSS 文件是否真的被引入。
- 选择器是否写错，类名是否和模板一致。
- 样式是否被后面的规则覆盖。
- 组件作用域样式是否影响了选择器。
- 浏览器 DevTools 里元素是否能看到这条样式。

如果样式在 DevTools 里被划掉，通常说明优先级或加载顺序有问题。如果样式完全看不到，通常是文件没有加载、选择器没匹配或构建入口没引入。

## 2. 元素无法水平垂直居中

优先使用 Flex 或 Grid，不要一上来就用定位硬调。

```css
.center {
  display: flex;
  align-items: center;
  justify-content: center;
}
```

如果还是没有居中，检查父容器是否有明确高度。很多“垂直居中失败”其实是父元素没有可用于居中的高度。

## 3. 点击事件没有触发

常见原因：

- 事件绑定的元素不是实际点击的元素。
- 元素被别的层遮住了。
- 按钮被设置了 `disabled`。
- 自定义组件没有正确向外 `emit` 事件。
- 表单按钮默认触发提交，导致页面刷新。

排查时可以先在事件里写 `console.log`，再用 DevTools 的 Elements 面板看点击区域和层级。

## 4. 接口请求失败

先看 Network 面板，不要只看控制台报错。

重点检查：

- 请求 URL 是否正确。
- 请求方法是 `GET`、`POST` 还是其他。
- 请求参数是否按后端要求发送。
- 状态码是 `401`、`403`、`404` 还是 `500`。
- 响应体里有没有具体错误信息。
- 是否出现 CORS 跨域错误。

如果是跨域，前端通常不能单独解决，需要服务端配置 CORS，或者开发环境使用代理。

## 5. 页面刷新后路由 404

单页应用常见问题。开发时通过前端路由跳转没问题，但刷新页面后服务器找不到对应路径。

解决思路：

- 使用 Hash 路由，例如 `/#/posts`。
- 或者让服务器把所有前端路由都回退到 `index.html`。

当前这个博客使用的是 Hash 路由，所以部署静态站时会更省心。

## 6. Vue 数据变了但页面没更新

常见排查点：

- 状态是否用 `ref` 或 `reactive` 创建。
- 模板里是否忘了使用 `.value` 之外的正确访问方式。
- 是否直接修改了不该由当前组件修改的 props。
- 是否用数组索引或对象深层字段造成逻辑混乱。
- 派生数据是否应该使用 `computed`。

如果一个值可以由其他状态计算得到，优先使用 `computed`，不要用 `watch` 手动同步。

## 7. 列表渲染出现错位

`v-for`、React 的 `map` 渲染列表时，都需要稳定的 key。不要随手用数组下标当 key，尤其是在列表会插入、删除、排序的时候。

```vue
<PostCard
  v-for="post in posts"
  :key="post.slug"
  :post="post"
/>
```

稳定 key 可以帮助框架正确复用节点，避免输入框内容错位、动画异常、状态串到别的项上。

## 8. 本地正常，线上白屏

线上白屏先看三处：

- Console 是否有 JavaScript 报错。
- Network 是否有资源 404。
- 构建产物路径是否和部署目录匹配。

如果项目部署在子目录，比如 `/blog/`，构建配置里的 `base` 就很关键。资源路径不对时，页面可能只加载了 HTML，没有加载到 JS 和 CSS。

## 9. 打包失败或依赖安装失败

常见处理顺序：

1. 先读完整错误信息，找到第一个真正报错。
2. 确认 Node.js 版本是否符合项目要求。
3. 确认包管理器是否一致，比如项目用 `yarn.lock` 就优先用 `yarn`。
4. 删除本地临时缓存前，先确认不是代码语法错误。
5. 仍然失败时，再考虑重装依赖。

不要看到报错就直接删除所有文件重来。构建错误通常会告诉你具体文件、行号或依赖名。

## 10. 性能感觉很慢但不知道慢在哪里

不要凭感觉猜。可以先做三步：

- Network：看资源是否太大、接口是否太慢。
- Performance：录制交互，找长任务和频繁渲染。
- Lighthouse 或 PageSpeed Insights：看首屏、可访问性和最佳实践建议。

如果是首屏慢，通常先看资源体积和接口耗时。如果是操作卡，通常看运行时计算、列表渲染和频繁 DOM 更新。

## 一个通用排查公式

遇到问题时可以按这个顺序问：

1. 问题能稳定复现吗？
2. 是结构、样式、脚本、请求、构建还是部署问题？
3. 浏览器面板里有没有证据？
4. 最近改动了哪些文件？
5. 能不能写一个最小复现？

会排查问题，比记住某个具体答案更重要。前端知识很多，但问题定位的能力会把这些知识真正串起来。
