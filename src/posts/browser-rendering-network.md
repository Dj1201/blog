前端代码最终运行在浏览器里。理解浏览器的工作方式，可以帮助我们解释页面为什么慢、样式为什么闪、请求为什么被缓存。

## 从输入 URL 到页面展示

一次页面访问大致会经历这些步骤：

1. 解析 URL，确认协议、域名、路径。
2. 查询 DNS，把域名解析成 IP。
3. 建立连接，HTTPS 还会进行 TLS 握手。
4. 发送 HTTP 请求。
5. 接收 HTML、CSS、JavaScript、图片等资源。
6. 解析资源并渲染页面。

真实过程会受到缓存、重定向、预加载、HTTP 版本等因素影响，但这条主线足够帮助我们排查大部分问题。

## 渲染流程

浏览器渲染页面通常包括：

- 解析 HTML，生成 DOM。
- 解析 CSS，生成 CSSOM。
- 合并生成渲染树。
- 计算布局。
- 绘制。
- 合成。

JavaScript 可能会阻塞 HTML 解析，CSS 也会影响渲染，所以关键资源越大，首屏越容易慢。

## 回流与重绘

回流是重新计算元素布局，重绘是重新绘制视觉效果。改变元素尺寸、位置、字体可能触发布局计算；改变颜色、阴影通常只触发绘制。

优化思路：

- 批量读写 DOM，避免读写交错。
- 动画优先使用 `transform` 和 `opacity`。
- 大量列表不要一次性全部渲染。
- 使用 CSS class 批量修改样式。

## HTTP 缓存

缓存可以减少重复请求。常见响应头包括：

- `Cache-Control`：控制资源缓存策略。
- `ETag`：资源标识，用于协商缓存。
- `Last-Modified`：资源最后修改时间。

静态资源通常会加 hash 文件名，然后设置较长缓存时间。HTML 则通常缓存时间较短，确保用户能拿到最新资源入口。

## 请求状态码

常见状态码：

- `200`：请求成功。
- `301` / `302`：重定向。
- `304`：协商缓存命中。
- `400`：请求参数有问题。
- `401`：未认证。
- `403`：无权限。
- `404`：资源不存在。
- `500`：服务端错误。

调试接口时，不只看状态码，也要看请求方法、请求头、响应体和实际发出的 URL。

## 跨域

浏览器同源策略会限制不同源之间的请求访问。跨域通常通过 CORS 解决，由服务端返回允许访问的响应头。

前端看到跨域报错时，不能只在客户端修改代码。很多情况下需要服务端正确配置 `Access-Control-Allow-Origin` 等响应头。

## 小结

浏览器知识能把很多“玄学问题”还原成可观察的过程。遇到加载慢、请求异常、缓存不更新、页面抖动时，先打开 DevTools，看 Network、Performance 和 Elements 面板，问题通常会清楚很多。
